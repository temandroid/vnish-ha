## Возможности

| Тип | Сущности |
|---|---|
| **Сенсоры** | Хэшрейт (реальный / средний / номинальный / заводской), потребляемая мощность (Вт), эффективность (Дж/ТХ), температуры платы и чипов (мин/макс), обороты вентиляторов (%) и RPM каждого, аппаратные ошибки (% и счётчик), частота ошибок, состояние майнера и время в нём, счётчик перезапусков, активный пул, принятые/отклонённые/устаревшие шары, пинг пула, аптайм, свободная память. По каждой плате — хэшрейт, температуры, ошибки, состояние. Температуры БП, если прошивка их отдаёт |
| **Бинарные сенсоры** | Майнинг (работает / остановлен), отказ каждого вентилятора, «требуется перезапуск майнинга» и «требуется перезагрузка» (флаги `restart_required` / `reboot_required` из `GET /status`; на прошивке без `/status` не создаются) |
| **Переключатель** | Майнинг вкл/выкл |
| **Число** | Троттлинг (20–100%); команды идут на майнер не чаще раза в 15 с, см. ниже |
| **Кнопки** | Перезагрузка, перезапуск майнинга, пауза, возобновление |
| **Выбор** | Активный пул (пулы DevFee и Refund не показываются) |

## Требования

- ASIC-майнер с прошивкой Vnish (AnthillOS)
- Home Assistant 2024.12+ (своя иконка интеграции видна с 2026.3)

## Установка

### Marketplace (HA 2026.11+, рекомендуется)

С Home Assistant 2026.11 HACS встроен в ядро как **Marketplace**; установка из HACS
переезжает туда сама при первом запуске после обновления.

1. Настройки → Marketplace → ⋮ → Пользовательские репозитории
2. Добавить `temandroid/vnish-ha`, категория `Integration`
3. Установить и перезапустить HA

Marketplace предлагает версии по **GitHub-релизам** (не по тегам) и не даст
поставить релиз на HA старее 2024.12 — минимум указан в `hacs.json`.

### HACS (HA до 2026.11)

1. HACS → Настройки → Пользовательские репозитории
2. Добавить `temandroid/vnish-ha`, категория `Integration`
3. Установить и перезапустить HA

### Вручную

Скопировать `custom_components/vnish/` в `<HA config>/custom_components/`.

## Настройка

1. Настройки → Устройства и службы → Добавить интеграцию → **Vnish Miner**
2. Ввести IP-адрес майнера (например `192.168.1.100`)
3. Опционально — API-ключ (создаётся в веб-интерфейсе прошивки → API Keys)

Интервал опроса (по умолчанию 30 сек) меняется через **Настроить** на карточке интеграции.

## Протестировано на

- Antminer S19k Pro, Vnish 1.3.3
- Antminer S21+ Hydro, Vnish 1.3.5

## API

Интеграция использует локальный REST API `/api/v1` прошивки Vnish.

`GET /summary` и `GET /info` доступны без авторизации. Управление (старт, стоп, пауза, перезапуск, ребут, смена пула, троттлинг) требует API-ключ (`x-api-key`) или пароль веб-интерфейса: пароль обменивается на JWT через `POST /unlock`.

### Троттлинг: пауза между командами

Каждый `POST /mining/throttle` заставляет Vnish заново применить пресет производительности, это занимает около 10 с. Команда, пришедшая в это окно, теряется (`WARN: Overclocking settings setup in progress` в логе майнера), после чего майнер ставит `restart_required` и работает не на тот процент, который показывает. Лечится только перезапуском майнинга.

Поэтому с v1.6.0 интеграция шлёт троттлинг не чаще раза в 15 с, кто бы его ни менял:

- запись, пришедшая после паузы, уходит на майнер сразу, и вызов `number.set_value` ждёт ответа, как раньше (ошибка связи с майнером вернётся в вызов сервиса);
- записи внутри паузы не ждут: сервис возвращается сразу, ползунок показывает новое значение, а на майнер после паузы уходит только **последнее** значение. Серия из любого числа быстрых записей стоит майнеру не больше двух команд;
- если отложенное значение совпадает с уже применённым, команда не отправляется.

Если `restart_required` всё же включился (например, прошивка сама меняла пресет в момент команды), помогает кнопка «Перезапустить майнинг».
